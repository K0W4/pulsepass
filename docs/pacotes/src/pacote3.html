1. Resumo do checkpoint

O repositório contém a fatia vertical R1 do PulsePass: do catálogo de eventos até o ingresso validado na portaria, passando por reserva atômica, pagamento idempotente, Outbox e Kafka, agora com a SPA, observabilidade, testes de carga, réplicas e teste de resiliência. Tudo sobe com docker compose up -d --wait e o script scripts/smoke.sh percorre o fluxo completo pelo gateway, autenticando no Keycloak (inclusive o auto-cadastro).

Testes automatizados62, todos passando: 21 unitários, 25 de integração com PostgreSQL, Redis e Kafka reais (Testcontainers), 3 do simulador, 5 do gateway e 8 do front-end.

Limites honestos. As medições de carga foram feitas num laptop, sem latência de rede real; servem para verificar as metas, não como benchmark. A cobertura de 70% mede o pacote domain (máquinas de estado e regras puras); a orquestração dos serviços é exercida pelos testes de integração, mas não entra nesse percentual. O axe-core e o Lighthouse foram executados à mão, não na CI. As proteções de branch do GitHub não foram configuradas. A leitura do QR na portaria é por digitação do código.

1.1 Como reproduzir

cp .env.example .env
docker compose up -d --build --wait     # SPA em http://localhost:3000
./scripts/smoke.sh
./scripts/replicas.sh                   # 2 réplicas de cada serviço
./scripts/resiliencia.sh                # derruba a Emissão durante uma compra
./scripts/carga.sh                      # k6: catálogo a 1.000 req/s e reserva a 200 req/s
./mvnw verify                           # unitários + integração + formatação + cobertura do domínio
(cd frontend && npm ci && npm test && npm run build)
docker compose down -v

Pré-requisitos: Docker com Compose e Java 21 (o Maven vem pelo wrapper). O README.md do repositório traz os detalhes, as portas e os testes que sustentam cada requisito.

5. Atualizações do Pacote 1

O Pacote 1 entregue continua válido. As atualizações são estas:

  • Backlog: o status por história está na seção 2. Nenhuma história foi removida; as de R2 e R3 não citadas seguem como candidatas.
  • Regras esclarecidas durante a construção: (1) o pedido nasce CRIADO e vira RESERVADO quando a reserva é confirmada pelo evento do Inventário; (2) pagamento recusado ou falha do gateway devolvem o pedido a RESERVADO, para nova tentativa enquanto a reserva estiver ativa; (3) a capacidade de um lote é controlada por contadores (qtd_reservada e qtd_vendida); (4) a expiração da reserva fica suspensa por até 30 s durante o pagamento.
  • Processo com IA (SDD): as três funcionalidades críticas têm spec em /specs (reserva atômica, pagamento idempotente, ingresso com QR), escritas antes do código. As regras dos agentes estão versionadas em .claude/CLAUDE.md. O código foi gerado com apoio do Claude Code e revisado pelo grupo; os testes de integração, o smoke e a verificação da SPA no navegador serviram de contrapeso e acharam defeitos reais, descritos abaixo.
  • Ferramentas efetivamente usadas: Java 21, Spring Boot 3.5, Maven, Testcontainers, PIT, k6, GitHub Actions, Docker Compose, Keycloak, OpenTelemetry, Prometheus, Grafana, Jaeger, Vite e TypeScript. Figma, GitHub Projects e Structurizr continuam previstos.
  • Front-end (Pacote 1, seção 5): a SPA foi implementada seguindo a estrutura e o mapa de navegação dos mockups: catálogo, detalhe, mapa de assentos, checkout com contagem regressiva, meus ingressos, painel e cadastro do organizador e leitor da portaria. O status do pedido em tempo real (tela 5) é feito dentro do checkout, por polling; a tela de administração (tela 10) e a leitura do QR por câmera ficam para o Pacote 4.

5.1 Defeitos achados pelos testes e corrigidos

  • Chave de idempotência reutilizada após falha do gateway: o pagamento falho mantinha a chave e a nova tentativa violava a unicidade (achado em CheckoutIT).
  • Erros 409, 422 e 404 virando 403: o redirecionamento para /error caía na regra de negação do Spring Security. Os testes com MockMvc não veem isso; o smoke contra o Compose real encontrou.
  • Tópico criado com 1 partição: corrida de criação de tópicos entre serviços; corrigida com o contêiner kafka-init e criação automática desligada.
  • Limite do segredo do QR: mutante sobrevivente (32 contra 31 caracteres) fechado com teste de fronteira.
  • Papel padrão sem efeito no auto-cadastro: o Keycloak só importa os papéis compostos pela lista de papéis do realm; quem se cadastrava não recebia o papel cliente. Corrigido e coberto pelo smoke.
  • Gateway devolvia 500 com o serviço fora do ar: agora responde 503 (teste em RotasTest; achado pelo teste de resiliência).
  • Trace partido pelo Outbox: a publicação assíncrona perdia o contexto; o traceparent passou a ser gravado na linha do Outbox e reaplicado pelo relay.
  • Ordem dos assentos e dos ingressos na SPA: a ordem alfabética (A1, A10, A11, A2) foi trocada por ordem natural, e os ingressos mais novos aparecem primeiro.
